# T03.1: Seed data (administrator and demo heroes)

**User story:** [US-001](../US-001-SuperHero-Registry.md) · **Layer:** Infrastructure · **Estimate:** 2 h · **Depends on:** T03 · **Status:** Done

## Goal
On first start, create the demo administrator and three heroes, so the application can be demonstrated right away (AC10).

## Approach
The seed data is a **SQL migration script**, `Persistence/Scripts/0003_SeedData.sql`. The T03 migrator applies it exactly once, right after the schema scripts, under both Aspire and Docker Compose. This keeps T03.1 independent of the domain model (T04), the repositories (T06) and the password hasher (T08).

Trade-offs of a SQL script compared with a code seeder:
- **Domain rules:** the seed rows do not go through `SuperHero.Create(...)`. They are still checked by the database's CHECK and unique constraints (T03), and the `SeedDataTests` pin the exact values. Once T04 exists, a test can also verify them against the domain rules (see below).
- **Password:** it is stored as a **precomputed BCrypt hash** in the script, so it cannot be changed through configuration. The `Seed:AdminPassword` setting from the earlier plan does not apply. To use a different password, generate a new hash and add a new numbered script (never edit `0003`), or change it through the application once a change-password feature exists.

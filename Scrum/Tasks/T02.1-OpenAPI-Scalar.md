# T02.1: OpenAPI document and Scalar API reference

**User story:** [US-001](../US-001-SuperHero-Registry.md) · **Layer:** API · **Estimate:** 2 h · **Depends on:** T02 · **Status:** Done

## Goal
Give developers and reviewers an interactive, always up-to-date API reference. The API publishes an OpenAPI document, Scalar renders it, and starting the API in development (F5, `dotnet watch`, the Aspire dashboard) leads directly to Scalar.

## Steps
- [x] Add `Scalar.AspNetCore` to the Api project (Central Package Management).
- [x] Describe the API in the OpenAPI document with a document transformer:
  - Title: "Hero Registry API"
  - Version: `v1`
  - A short description
- [x] In Development only:
  - Map `/openapi/v1.json` (`MapOpenApi`).
  - Map the Scalar UI at `/scalar` (`MapScalarApiReference`): title, Purple theme, and C# `HttpClient` as the default code sample.
  - Redirect `/` to `/scalar`, so the API's base URL opens the reference. The redirect is excluded from the OpenAPI document.
- [x] Keep the OpenAPI document and Scalar **off** outside Development. They describe the attack surface.
- [x] Launch settings: the `http`, `https` and `Container (Dockerfile)` profiles use `launchBrowser: true` and `launchUrl: "scalar"`.
- [x] Aspire dashboard: add a **"Scalar API Reference"** link on the `api` resource (`WithUrlForEndpoint`).
- [x] Update `HeroRegistry.Api.http` and the README (URLs and tech stack).

## Out of scope
- JWT Bearer security scheme in the OpenAPI document and Scalar's "Authorize" support. These are moved to T11, after authentication exists (T09).
- XML-comment-driven descriptions for each endpoint. These are added with the controllers (T09, T10).

## Implementation notes
- **Version:** `Scalar.AspNetCore` **2.19.0**. The 3.x line had been out less than a week and is a new major version, so it was left for a deliberate upgrade.
- **Code:** `HeroRegistry.Api/OpenApi/ApiDocumentationExtensions.cs` provides `AddApiDocumentation()` and `MapApiDocumentation()`, which keeps `Program.cs` short. The Development-only check lives inside `MapApiDocumentation()`.
- **Trailing slash:** Scalar answers `/scalar` with a 302 to `/scalar/`, which then serves the page. This is Scalar's normal behavior.
- **Verified under Aspire:**
  - `/health` returned `Healthy`.
  - `/` redirected to `/scalar`, and `/scalar/` served the "Hero Registry API" page.
  - `/openapi/v1.json` listed `/api/v1/test`.
  - The UI still returned 200.
- **Container profile:** the `Container (Dockerfile)` launch profile now sets `ASPNETCORE_ENVIRONMENT=Development`, so Scalar is available when debugging in a container from Visual Studio. Its launch URL changed from `/api/v1/test` to `/scalar`.
- **`dotnet run`:** plain `dotnet run` does not open a browser. Use F5 or `dotnet watch` for that, or open http://localhost:5103 (which redirects to Scalar).
